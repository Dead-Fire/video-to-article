# 视频转字幕与 GPT 阅读稿处理包

这是一个轻量 Windows 本地工具，用于把下载好的视频或音频转换成字幕和可直接粘贴给 GPT 的阅读稿处理包。

第一版不接入任何在线 API，也不内置大语言模型。工具负责本地提取/识别字幕、轻度清洗、自查标记和生成 Markdown；后续整理交给 GPT 新对话手动处理。

## 运行方式

首次使用如需拖放功能，请安装轻量拖放依赖：

```powershell
py -3 -m pip install -r requirements.txt
```

双击 `run.bat`，或在当前目录运行：

```powershell
py -3 main.py
```

打开窗口后，可以直接把视频、MP3 等音频文件，或包含媒体文件的文件夹拖到窗口里。程序会按扩展名自动识别视频/音频并加入待处理列表。如果拖放依赖不可用，仍可以使用“选择视频”和“选择文件夹”按钮。

可以一次拖入多个文件。多文件会作为同一个批次处理，统一输出到 `output/批量任务/批量任务_日期时间/` 文件夹里；每个源文件的字幕结果在这个批次目录下各自一个子目录，批量整合结果也放在同一个批次目录中。单个文件会输出到 `output/单文件任务/`。

处理完成后点击“打开输出目录”，会优先打开当前任务实际生成的完整结果目录；如果在左侧列表选中了某个已处理媒体，会打开这个媒体对应的结果目录。点击“打开 GPT 文件夹”会直接打开当前任务的 `00_拖给GPT/`，这是最适合无脑拖给 GPT 的入口。

主界面会显示处理队列状态，包括当前文件、已完成数量、成功/失败数量和剩余数量。处理过程中也会写入：

```text
output/队列状态.txt
```

这个文件适合长任务时随时打开查看；显示“全部完成”时，本轮任务已经结束。

当一次处理 20 个或更多媒体文件时，程序会自动启用大批量省资源模式：

- 仍然逐个串行处理，不并发跑多个 whisper/ffmpeg。
- GUI 只保留最近日志，完整关键日志写入每个任务的 `04_日志与调试/处理日志.txt`。
- 子进程输出只记录尾部摘要，避免长视频日志撑爆内存。
- 长时间运行的 ffmpeg/whisper 阶段会每 60 秒写一次“仍在运行，已耗时 X”的心跳日志，方便判断不是卡死。
- 主界面和 `output/队列状态.txt` 会持续显示当前处理到第几个文件，不需要守着日志窗口。
- 视频关键截图数量会自动减少，画面变化检测改为每秒抽样，降低 CPU、磁盘和压缩包体积。
- 批量整合只跳过完全重复片段，不做高成本全文模糊比对。

## 目录说明

- `input/`：可以把待处理视频或音频放到这里。
- `output/`：每个视频会生成一个单独输出目录。
- `templates/gpt_prompt.md`：发给 GPT 的提示词模板。
- `config/术语词库.txt`：每行一个术语，会自动写入 GPT 处理包。
- `tools/ffmpeg/`：放置 `ffmpeg.exe` 和 `ffprobe.exe`。
- `tools/whisper/`：放置 `whisper-cli.exe`。
- `tools/whisper/models/`：放置 whisper.cpp 模型文件。

## 外部依赖

程序优先查找：

```text
tools/ffmpeg/ffmpeg.exe
tools/ffmpeg/ffprobe.exe
tools/whisper/whisper-cli.exe
tools/whisper/models/ggml-small.bin
```

也会自动查找系统 PATH 中的 `ffmpeg`、`ffprobe` 和 `whisper-cli`。

手动下载后，可以双击 `检查依赖.bat` 确认工具是否已经找到这些文件。

### 手动下载放置

1. 下载 FFmpeg Windows build，推荐 essentials build。
2. 从压缩包里找到 `bin/ffmpeg.exe` 和 `bin/ffprobe.exe`，复制到：

```text
tools\ffmpeg\
```

3. 下载 whisper.cpp Windows release，并将 `whisper-cli.exe` 及其运行所需 DLL 放入 `tools/whisper/`。
4. 把 `whisper-cli.exe` 复制到：

```text
tools\whisper\
```

5. 下载 whisper.cpp 模型 `ggml-small.bin`，复制到：

```text
tools\whisper\models\
```

如果视频本身带有文本字幕轨，只需要 `ffmpeg` 和 `ffprobe`。如果没有字幕轨，或输入的是 MP3 等音频文件，需要额外准备 `whisper-cli.exe` 和模型文件。

直接使用 MP3 通常比视频更省资源，因为文件更小，也会跳过视频字幕轨检测；程序仍会先用 `ffmpeg` 转成 16kHz 单声道 WAV，再交给 whisper.cpp 识别。

## 输出文件

每个单文件任务会输出一个清晰分区的目录：

- `00_先看我_使用说明.md`：打开结果目录后优先看这个，里面写明下一步该发哪个文件。
- `00_拖给GPT/`：直接拖给 GPT 的入口。
- `02_字幕稿/`：原始字幕、纯文本字幕、轻度清洗稿。
- `03_截图素材/`：完整关键截图、截图索引、候选数据。
- `04_日志与调试/`：处理日志、whisper 运行信息、调试文件。

`00_拖给GPT/` 中会放好本次要发给 GPT 的素材：

- `发给GPT.md`
- 如果是视频任务并且生成了截图，还会有 `图文总结图片.zip`

关键截图使用更严格的字幕规则和画面变化检测生成；如果输入是 MP3 等音频文件，会跳过截图功能。

只有文字稿时，拖 `00_拖给GPT/`。视频生成了截图，并且你希望 GPT 输出图文并茂的总结文章时，也拖这个同一个文件夹；图片已经被工具自动打包成 `图文总结图片.zip`。

新版提示词会要求 GPT 优先直接生成一份排版清晰的 PDF 文章。如果当前 GPT 对话不能生成 PDF 文件，它会输出一篇可复制到 Word、飞书文档或 Markdown 编辑器并导出 PDF 的完整排版稿，而不是只给普通摘要。

批量处理 2 个或更多文件时，会在同一个批次目录中生成：

- `整合结果/00_先看我_使用说明.md`
- `整合结果/00_拖给GPT/`
- `整合结果/00_拖给GPT/图文总结图片.zip`：如果本批次有截图，会自动放入批量精选截图，和 `发给GPT.md` 一起上传。
- `整合结果/02_整合稿/整合字幕.txt`
- `整合结果/02_整合稿/整合阅读稿.md`
- `整合结果/03_截图素材/`：保留每个源视频自己的关键截图、截图索引和候选数据。
- `整合结果/04_日志与调试/重复片段.json`
- `整合结果/04_日志与调试/整合清单.json`

批量整合会读取每个文件的 `02_字幕稿/轻度清洗字幕.txt`，按段落合并，并跳过完全重复或高度相似的片段。

大批量省资源模式下，批量整合会优先保证稳定和速度，只跳过完全重复片段；这不会强行寻找每段音频之间的重复点。

## 从 GitHub 获取

克隆仓库后，在项目目录运行：

```powershell
py -3 -m pip install -r requirements.txt
py -3 main.py
```

`run.bat` 也可以直接启动程序。请预先安装 Python 3；媒体处理工具和 Whisper 模型不随仓库分发，请按上文放置，或将可执行文件安装到系统 `PATH`。`input/`、`output/` 和本地 `tools/` 内容已由 `.gitignore` 排除。

## 第一版范围

- 支持 Windows 本地使用。
- 支持常见视频格式：`mp4`、`mkv`、`mov`、`avi`、`flv`、`wmv`、`m4v`、`webm`、`ts`。
- 支持常见音频格式：`mp3`、`wav`、`m4a`、`aac`、`flac`、`ogg`、`opus`、`wma`。
- 优先提取视频内置文本字幕轨。
- 没有字幕轨时，使用 whisper.cpp 做本地语音识别。
- 不做画面硬字幕 OCR。
- 不做说话人分离。
- 不接入 OpenAI API 或其他在线 API。
